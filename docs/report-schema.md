# Report schema (draft v0)

Status: **v0 implemented** for run, navigation, requests, TLS, domains, dialogs, downloads, artifacts and gaps (P2), and the host-attested `network.dns`, `network.flows`, `network.blocked` and `reconciliation` (P3; reconciliation's shape differs from the sample below, see the proto). `page.forms` and `page.password_fields` (from the final DOM; top document only), `page.screenshot_phash` and `page.screenshot_blank` (P7 side quest): a 64-bit DCT perceptual hash of the screenshot, for finding pages that look alike (`internal/visual`). Source of truth: [`api/proto/urljail/report/v0/report.proto`](../api/proto/urljail/report/v0/report.proto); JSON Schema: [`api/schema/report.v0.schema.json`](../api/schema/report.v0.schema.json) (generated by `make gen`, checked by a test). The sample below is the design target; `indicators` come later.

`report.json` is *derived* from raw artifacts (see storage layout in [architecture.md](./architecture.md#storage-layout-per-run)) and can always be regenerated. Every observation carries its **source** so readers know who attests to it.

## Sources

| `source` | Meaning | Trust |
| -------- | ------- | ----- |
| `host.ebpf` | eBPF on the VM's TAP device | high (outside the guest) |
| `host.pcap` | packet capture (+ key log decryption) | high for metadata; payload decryption depends on guest-supplied keys |
| `host.dns` | our resolver's log | high |
| `host.fw` | nftables drop logs | high |
| `guest.cdp` | Chromium DevTools Protocol events | guest-attested |
| `guest.agent` | guest agent (screenshot, DOM) | guest-attested |

## Open schema questions

- ~~Source of truth~~: decided and implemented. Protobuf in `api/proto/`, `report.json` via protojson (`UseProtoNames`), JSON Schema generated from the proto ([ADR 0008](./decisions/0008-protobuf-report-schema.md)). This page stays the readable reference. The proto package is `urljail.report.v0`; buf's lint only accepts `v1`+ package versions, so `buf.yaml` exempts that one directory from `PACKAGE_VERSION_SUFFIX`.
- ~~Refused runs~~: decided in P2. A run refused at preflight (policy, busy, bad timeout) never gets a run directory or report: nothing ran. The refusal goes back to the client and into the daemon log.
- Browser background traffic (some GCM to `mtalk.google.com` remains, see [guest-image.md](./guest-image.md#chromium-configuration)): label known browser-background destinations in the report rather than hide them.
- HAR export for interop with existing tools (cheap to add from CDP events).
- Perceptual hash of screenshot (pHash) for visual similarity / brand matching later.
